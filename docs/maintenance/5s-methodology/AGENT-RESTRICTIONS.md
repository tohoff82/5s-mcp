# 🚫 Обмеження для LLM Агентів при 5S Процедурах

## АБСОЛЮТНІ ЗАБОРОНИ

### 🔴 НІКОЛИ НЕ ВИКОНУВАТИ без backup:
```bash
# ЗАБОРОНЕНО БЕЗ BACKUP:
rm -rf /root/ui-agent/*
systemctl stop ui-agent-*
rm /etc/systemd/system/ui-agent-*
rm /etc/nginx/sites-*/ui-agent*
```

### 🔴 ЗАБОРОНЕНІ ДИРЕКТОРІЇ для автоматичного очищення:
- `/root/ui-agent/services/` - власні сервіси
- `/root/ui-agent/shared/` - спільний код
- `/root/ui-agent/docs/` - документація
- `/etc/systemd/system/ui-agent-*` - systemd файли
- `/etc/nginx/sites-*/` - nginx конфіги

### 🔴 ЗАБОРОНЕНІ ОПЕРАЦІЇ:
- Видалення логів новіших за 7 днів
- Масштабні операції `find -delete` без dry-run
- Зміна прав доступу критичних файлів
- Переміщення активних конфігурацій

## ⚠️ ОБЕРЕЖНО З:

### MongoDB та RabbitMQ:
- НЕ видаляти бази даних без backup
- НЕ очищувати всі queues одночасно
- Перевіряти активні з'єднання перед змінами

### Системні логи:
- Ротація тільки через logrotate
- НЕ видаляти поточні логи сервісів
- Зберігати останні 30 днів логів

### Мережеві конфігурації:
- НЕ змінювати налаштування nginx без тестування
- НЕ модифікувати SSL сертифікати
- НЕ змінювати файрвол правила

## ✅ ДОЗВОЛЕНІ ОПЕРАЦІЇ

### Безпечне очищення:
```bash
# ДОЗВОЛЕНО:
# Старі логи (30+ днів)
find /var/log -name "*.log.*.gz" -mtime +30 -type f

# Тимчасові файли
find /tmp -type f -mtime +7 -not -path "*/ui-agent/*"

# Package cache
apt autoremove --dry-run
apt autoclean --dry-run
```

### Організація файлів:
- Сортування в межах /var/log
- Очищення package cache
- Організація backup директорій
- Стандартизація назв логів

## 🔧 БЕЗПЕЧНІ КОМАНДИ

### Аналіз БЕЗ змін:
```bash
# Аналіз використання диску
du -sh /var/log/* | sort -hr
df -h
systemctl status ui-agent-*

# Аналіз процесів
ps aux | grep ui-agent
netstat -tlnp | grep ui-agent
```

### Dry-run операції:
```bash
# Перед видаленням - завжди показати список
find /var/log -name "*.log.*.gz" -mtime +30 -type f -ls
# І тільки після підтвердження:
find /var/log -name "*.log.*.gz" -mtime +30 -type f -delete
```

## 📋 ОБОВ'ЯЗКОВІ КРОКИ

### Перед кожною операцією:
1. Backup системи
2. Dry-run симуляція  
3. Показ списку змін користувачу
4. Отримання підтвердження
5. Поетапне виконання
6. Перевірка після кожного кроку

### При помилках:
1. НЕГАЙНО зупинити операцію
2. Записати помилку у лог
3. НЕ продовжувати без аналізу
4. Готуватися до відкату з backup
