# 🚨 КРИТИЧНІ ЗАСОБИ ЗАХИСТУ ВІД САМОРЕФЕРЕНТНИХ РИЗИКІВ

## ОБОВ'ЯЗКОВО ЧИТАТИ ПЕРЕД ВИКОНАННЯМ 5S ПРОЦЕДУР

### Проблема Самореферентності
UI-Agent виконує процедури 5S на сервері, де він сам знаходиться. Це створює критичні ризики:

1. **Самознищення** - агент може видалити власні файли
2. **Самоблокування** - може зупинити власні сервіси
3. **Циклічні помилки** - помилки у процедурах можуть призвести до краху системи
4. **Втрата контролю** - якщо агент зіпсує себе, відновлення стане складним

## 🛡️ ОБОВ'ЯЗКОВІ ЗАСОБИ ЗАХИСТУ

### Перед КОЖНОЮ 5S процедурою:

1. **СТВОРИТИ ПОВНУ КОПІЮ СИСТЕМИ**
   ```bash
   # Обов'язково!
   systemctl stop ui-agent-*
   tar -czf /backup/ui-agent-backup-$(date +%Y%m%d-%H%M%S).tar.gz /root/ui-agent/
   systemctl start ui-agent-*
   ```

2. **ПЕРЕВІРИТИ SYMBOLIC LINKS**
   - Переконатися, що критичні компоненти захищені символьними посиланнями
   - Ніколи не видаляти файли без перевірки, чи не є вони посиланнями

3. **ВИКОРИСТОВУВАТИ DRY-RUN РЕЖИМ**
   - Завжди спочатку симулювати операції
   - Показувати список файлів для видалення БЕЗ реального видалення

4. **ВСТАНОВИТИ ЧАСОВІ ОБМЕЖЕННЯ**
   - Операції очищення повинні мати timeout
   - Якщо процедура зависла - автоматично припинити

### Заборонені Операції під час 5S:

❌ **НІКОЛИ НЕ РОБИТИ:**
- `rm -rf` без детального аналізу
- Видалення файлів з `/root/ui-agent/` без backup
- Зупинка всіх ui-agent-* сервісів одночасно
- Очищення `/tmp/` без перевірки активних процесів
- Модифікація systemd unit files без backup

### Безпечні Операції:

✅ **БЕЗПЕЧНО:**
- Аналіз та звітування без змін
- Очищення логів старших за 30 днів (з backup)
- Організація файлів БЕЗ переміщення критичних компонентів
- Оптимізація конфігурацій з созданием backup

## 🔄 ПОСЛІДОВНІСТЬ БЕЗПЕЧНОГО ВИКОНАННЯ

1. **АНАЛІЗ** (Read-only операції)
2. **ПЛАНУВАННЯ** (Створення списку змін)
3. **BACKUP** (Повна копія системи)
4. **СИМУЛЯЦІЯ** (Dry-run всіх операцій)
5. **ПІДТВЕРДЖЕННЯ** (Запит дозволу у користувача)
6. **ПОЕТАПНЕ ВИКОНАННЯ** (По одній операції з перевіркою)
7. **ВЕРИФІКАЦІЯ** (Перевірка працездатності після кожного кроку)

## 🚨 ПЛАН ВІДНОВЛЕННЯ

Якщо щось пішло не так:

1. **НЕГАЙНО ЗУПИНИТИ** всі операції 5S
2. **ВІДНОВИТИ** з останньої копії:
   ```bash
   systemctl stop ui-agent-*
   cd /root
   rm -rf ui-agent/
   tar -xzf /backup/ui-agent-backup-[найновіший].tar.gz
   systemctl start ui-agent-*
   ```
3. **ПРОАНАЛІЗУВАТИ** що пішло не так
4. **ОНОВИТИ** засоби захисту
5. **ПРОТЕСТУВАТИ** відновлену систему

## 📊 МОНІТОРИНГ САМОРЕФЕРЕНТНОСТІ

Під час виконання 5S постійно відстежувати:
- Чи не зачіпаються власні файли агента
- Чи працюють всі сервіси ui-agent-*
- Чи є доступ до RabbitMQ та MongoDB
- Чи відповідає система на запити

## 🎯 ФІЛОСОФІЯ БЕЗПЕКИ

**"Краще не зробити, ніж зробити неправильно"**

У контексті самореферентної системи завжди краще:
- Перестрахуватися та зробити зайву копію
- Запитати підтвердження у користувача
- Виконати операцію поетапно з перевірками
- Залишити систему у працездатному стані
